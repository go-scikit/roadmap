# Parity plan: go-scikit and MATLAB / Mathematica

What the go-scikit stack must add to cover what MATLAB (base and toolboxes) and Mathematica
offer, in which order, and where each piece lives. The evidence (function inventories,
algorithms, reference implementations and licences, validation oracles and corpora) is in
[`bib/`](bib/), one file per domain.

## Rules every work item follows

- **Pure Go, CGO=0**, on every architecture the fleet's CI tests (amd64, arm64, 386, arm,
  riscv64, loong64, ppc64le, s390x, plus wasm where relevant).
- **Bibliography first**: an item starts from its `bib/` section, never from memory.
- **Validated against the tools that are the reference in the domain** (SciPy/NumPy, mpmath,
  Octave, PARI/GP, Maxima, SuiteSparse, NIST StRD, CUTEst, MIPLIB, the Rubi suite, …), with
  the measure the domain uses (ULPs, backward error, relative residual, certified values,
  exact equality). Reference tools are run as oracles, driven from Go; GPL/LGPL code is never
  ported, only compared against.
- **Tooling in Go**: generators, harnesses and comparisons are Go programs, tested like the
  rest; no shell, Python, Perl, awk or sed scripts.
- **Unit and regression tests at 100% coverage**, fixtures generated by Go harnesses, and a
  performance table against the reference tool: no slower than it on one core.
- Each item lands by pull request with CI green, is released with a tag, and updates the
  README, landing page and docs of its organisation.

## Waves

Ordered by what each unlocks and by dependencies; sizes from the `bib/` files.

**Wave 1 — the everyday MATLAB core, and self-hosted verification**
1. go-bignum: correctly rounded `big.Float` elementary functions and constants, and the Go
   oracle harness, so that accuracy is verified without Python's mpmath. (L)
2. go-sparse: CSR/CSC/COO, Matrix Market I/O, AMD/COLAMD/RCM orderings, CG/GMRES/BiCGSTAB/
   MINRES/LSQR with Jacobi/IC0/ILU0/ILUT. (M+M)
3. go-approx: interp1/interpn, PCHIP, Akima, cubic, B-splines, smoothing splines, polynomials. (L+M)
4. go-dsp: Butterworth/Chebyshev/elliptic/FIR design, lfilter/filtfilt/sosfilt, Welch, STFT,
   resample_poly, Hilbert, find_peaks. (L+L)

**Wave 2 — models and geometry**
5. go-numerics/optimize: SLSQP and an interior-point method, QP (active set, then ADMM),
   global methods (differential evolution, basin hopping, DIRECT). (L+M)
6. go-statistics/models: linear models and GLM with standard errors and ANOVA, certified on
   NIST StRD. (M)
7. go-geometry: exact predicates, Quickhull, Delaunay, Voronoi, alpha shapes, k-d trees. (S+L)
8. go-autodiff: forward (dual) and reverse (tape) modes, Jacobians and Hessians for optimize
   and integrate. (M)
9. go-units and go-sciio (HDF5, then MAT v7.3 on it; NetCDF, FITS, npy). (S + XL)
10. go-ndarray/linalg: Schur reordering, QZ, `expm`/`logm`/`sqrtm` (with the go-ndarray session).

**Wave 3 — systems, PDEs, 3D, interactivity**
11. go-plot/plot3d (surf, mesh, plot3, contour3, isosurface) and go-notebook `Manipulate`.
12. go-control: LTI models, frequency and time responses, Riccati/Lyapunov, LQR/LQG, c2d.
13. go-geometry meshing and go-fem (P1/P2 elements, Poisson, heat, elasticity), validated by
    manufactured solutions.
14. go-sparse direct solvers and sparse eigensolvers; go-dsp wavelets; go-approx Chebyshev/AAA.
15. go-mlkit (k-means, DBSCAN, GMM, trees and forests, SVM, cross-validation) and
    go-statistics/timeseries (ARIMA, state space, Kalman).
16. go-graphalgo (matching, isomorphism, communities, the centralities gonum lacks; gonum/graph
    already has max flow and betweenness — reuse, don't rewrite) and go-graphdrawing layouts.

**Wave 4 — Mathematica's core**
17. go-bignum ball arithmetic and N-digit special functions; number theory, seeded from
    go-ruby-prime's Miller–Rabin, Baillie–PSW, Pollard rho and sieve rather than rewritten
    (see [bib/ruby-reuse.md](bib/ruby-reuse.md)).

Code shared with the pure-Go Ruby: [bib/ruby-reuse.md](bib/ruby-reuse.md) lists where
go-embedded-ruby and the go-ruby-* gems duplicate go-scikit code. Rule: one implementation per
algorithm; the Ruby side keeps only what MRI fidelity requires (its own last-digit results,
decimal BigDecimal) and calls go-scikit for the rest. Changes inside rbgo and the go-ruby-*
repositories are proposed to the sessions that own them.
18. go-symbolic: expression DAG, polynomials over Z/Q/F_p, GCD and factorisation,
    differentiation, LaTeX through go-tex; then Gröbner bases, integration, series, limits.

Not planned: Mathematica's curated data (`Entity`, `CountryData`, …) and GPU computing (no
realistic pure-Go path).
